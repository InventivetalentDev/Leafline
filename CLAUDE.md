# CLAUDE.md

Guidance for any agent session working in this repository.

## Project

**Leafline** (Unreal project name `AntTreeGame`), Unreal Engine 5.8.4. You play a leafcutter ant on an enormous procedural tree: climb, lay a scent trail, cut a leaf fragment, send it home and shift to the next worker. Built solo with AI agents for two game jams.

Read in this order before doing anything:
1. `docs/design.md`: the game and the jam rules that constrain it.
2. `docs/tech.md`: architecture.
3. `docs/plan.md`: milestones, ownership, deadlines. Tick items as they land.

`docs/concept-main.md` is the owner's original notes; do not edit it. `docs/devlog.md` gets a short entry at each milestone. `docs/briefs/` holds self-contained briefs for parallel agents. `docs/tools.md` documents helper scripts; run the image metadata stripper before committing new photos.

## Hard rules

- **Clean room.** The MegaJam requires all game content to be created on or after 2026-11-12. An older prototype exists at `D:\UnrealProjects\TreeAntGame`. Never read, copy or adapt its source, assets, materials or Blender files. Other projects under `D:\UnrealProjects` are equally off limits as sources of game content.
- **Math only.** Tree, bark, leaves, ground, sky, trail and effects are procedural geometry and shaders. No textures, no hand-made tree models. The ant mesh (generated by a Blender script) is the one exception.
- **Nothing licensed goes in the repo.** It becomes public. No Fab or marketplace content. CC0 material is allowed and must be listed in `docs/sourced-assets.md`.
- **The repo is private until the owner says otherwise.** Never change its visibility or publish builds without an explicit yes in the current session.
- **One writer for binary assets.** Only the main session edits `.uasset` and `.umap` files.
- **Agents never submit.** The MegaJam rules require the entry to be submitted by the entrant, not by an AI agent or automated means. Prepare the build, zip, text and links; the owner submits on itch.
- **No trademarks or logos** in the game, video or page art, except the Unreal Engine logo used per Epic's branding guidelines.
- **Deadlines.** Feature freeze Sat 14 Nov 23:00 CET. Submit Sun 15 Nov 22:00 CET.
- All in-game text is English and suitable for a teen audience. Nothing that could read as cruelty to animals.

## Building

Create these two scripts in M0; always call them rather than passing quoted Windows paths through bash, which breaks the quoting.

`Scripts/build_editor.bat` (editor must be closed):
```
"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" AntTreeGameEditor Win64 Development -project="D:\UnrealProjects\AntTreeGame\AntTreeGame.uproject" -waitmutex
```

`Scripts/package_win64.bat` (Development configuration, as the jam asks):
```
"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\RunUAT.bat" BuildCookRun -project="D:\UnrealProjects\AntTreeGame\AntTreeGame.uproject" -platform=Win64 -clientconfig=Development -build -cook -stage -pak -prereqs -archive -archivedirectory="D:\UnrealProjects\AntTreeGame\Build" -noP4 -unattended -utf8output -WaitForUATMutex
```

Run with `cmd.exe /c "D:\UnrealProjects\AntTreeGame\Scripts\build_editor.bat"`.

Builds, packaging and standalone runs go through the machine-wide lock wrapper (`docs/tools.md`): `Scripts/unreal-lock.sh <holder> -- cmd.exe /c "D:\UnrealProjects\AntTreeGame\Scripts\build_editor.bat"`. Check `Scripts/unreal-lock.sh --status` before launching the editor. `Scripts/RunGame.bat` starts the game standalone without packaging.

Launch the editor detached, from `/mnt/c`, with the Bash tool's `run_in_background` (the command blocks until the editor exits). Keep `-ModelContextProtocolStartServer`: the plugin does not auto-start its server by default. Then wait for `Starting MCP server on port 8000` in `Saved/Logs/AntTreeGame.log`; unreal-mcp reconnects by itself.
```
cmd.exe /c start "" "C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor.exe" "D:\UnrealProjects\AntTreeGame\AntTreeGame.uproject" -ModelContextProtocolStartServer
```

Closing the editor (only when the owner says so, or has said it is fine):
1. `SlateInspectorToolset`: `Observe` window `w1` (maxDepth 40), then `Snapshot`.
2. Find the textbox right after the `text "Cmd"` button in the status bar (its ref changes between sessions).
3. `Type` `QUIT_EDITOR` with `submit: true` in a single `Type` call (repeat if it returns false), then wait for the process to exit.
- Never send `QUIT_EDITOR` inside a scripted batch: the batch's call stays open and the editor hangs at "Preparing to exit".
- If unreal-mcp is down, say so and ask the owner to close the editor or run `/mcp`. No `taskkill`, no hand-made MCP clients.

The same console textbox runs any console command (`LiveCoding.Compile`, `HighResShot 1`, `Leaf.*`); during Play In Editor it runs in the PIE world.

Editor setting "Use Less CPU when in Background" must stay off (set in `Config/DefaultEditorPerProjectUserSettings.ini`); with it on, PIE started over MCP runs at a few fps.

Two build paths:
- **Editor open, function bodies only:** Live Coding. Type `LiveCoding.Compile` into the editor console through the MCP UI tools, then watch `Saved/Logs/AntTreeGame.log` for the Live Coding result line.
- **Anything structural** (new classes, new or changed reflected members, `Build.cs`, plugins): ask the owner to close the editor, run the full build, relaunch.

Things that are known to bite:
- Live Coding patches live only in the running process. Do a full build before the next editor launch or old behaviour returns.
- Do not add or remove class members through Live Coding. Keep temporary debug state in file-local statics.
- UnrealBuildTool refuses to build while the editor's Live Coding session is active.
- A linker error saying the module DLL cannot be opened means a process still holds it. Wait and retry.
- There are no automated tests. Verification is Play In Editor driven over MCP plus the log.

## MCP servers (`.mcp.json`)

**unreal-mcp**: Epic's experimental ModelContextProtocol plugin at `http://127.0.0.1:8000/mcp`. It must be enabled in the `.uproject`. If it is not listening, the owner can run `ModelContextProtocol.StartServer` in the editor console. After an editor restart the owner may need to run `/mcp` to reconnect; Claude Code does not retry by itself.

- It exposes meta-tools to list toolsets, describe one, and call a tool. Start every session by listing and describing rather than assuming tool names; this plugin is experimental and changes between engine versions.
- Expect toolsets for materials, actors, scene, assets, Blueprints, static meshes, object properties, logs, starting and stopping Play In Editor, viewport capture, and driving the editor UI.
- A scripting tool can batch several tool calls in one request. Use it for material graphs: build the whole graph in one script, and rebuild it from scratch rather than patching nodes.
- Ask a node for its input pin names instead of guessing them.
- Never delete and recreate an asset under the same name in one editor session: the asset registry then reports it missing (`save_assets`, `exists`) although the file is on disk. Change nodes in place, or rebuild under a new name. `save_assets` with an empty list saves all dirty assets and sidesteps the lookup.
- `StaticMeshTools.import_file` imports FBX meshes. There is no audio import tool; sounds play at runtime from `Content/Leafline/AudioRaw/*.wavraw` (see `docs/tech.md`).
- Viewport captures come back as large base64 images; read them from the saved tool-result file.
- For in-game screenshots, run `HighResShot 1` in the console during play; files land in `Saved/Screenshots/WindowsEditor/`.
- Do not start or stop Play In Editor while the owner says they are playing.
- Double-clicking a C++ class in the editor can open a Windows "open with" dialog that blocks the editor, and every MCP call then times out until it is dismissed.

**blender-mcp**: talks to the Blender 5.1 add-on on `127.0.0.1:9876`. Blender must be running with the add-on enabled. Used only for the ant (and a bird, if the stretch goal is reached). See `docs/briefs/ant-mesh.md`.

**earshot**: listens to audio files locally. Use it to check synthesised sounds (`describe`, `match`, `ab`, `measure`) and quote its readings; never describe how a sound sounds without one. See `docs/briefs/audio.md`. It holds several GB of memory once used.

## Conventions

- All gameplay in C++ under `Source/AntTreeGame`. Blueprint subclasses in `/Game/Leafline/Blueprints` only for tuning values and asset references.
- Assets under `/Game/Leafline/` (`Maps`, `Materials`, `Meshes`, `Audio`, `Blueprints`).
- Input actions, mapping contexts and UI are created in code, not as assets.
- One log category, `LogLeafline`. Log gameplay events so they can be verified from the log.
- Debug console commands are prefixed `Leaf.` and listed in `docs/tech.md`. Add to that table when adding one.
- Keep tuning numbers in one struct per system, exposed to the Blueprint subclass.
